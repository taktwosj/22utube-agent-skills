# 초벌 대본 양식 — `script_draft_v1.md`

프로젝트 GPT가 쓴다. 산문은 자유롭게 쓰되 **출처 줄 하나만** 형식을 지킨다.

## 왜 마크다운인가

엄격한 JSON을 요구하면 cue 번호를 세다가 틀린다. 그 오류가 대본 오류로
둔갑해서 검수가 헛돈다. 그래서 사람이 쓰는 형태를 그대로 두고, 기계가 필요한
네 가지만 받는다.

```text
어느 소스인가 · 어느 구간인가 · 무엇을 뺐나 · 원문 그대로인가
```

이 넷이 있으면 인용 대조가 자동으로 끝난다. 직전 회차에서 사람이 전문을
읽어 잡던 일이다.

## 머리말

파일 맨 위에 둔다. 없으면 파싱 자체가 거부된다.

```markdown
---
episode_id: PL_20260727_politics_dp_convention_shincheonji
source_packet_sha256: <source_packet_v1.json 의 SHA-256>
narration_blocks: 16
source_clips: 13
---
```

`source_packet_sha256`은 어느 자막 묶음을 보고 썼는지 지문이다. 실제 패킷과
대조하므로 아무 값이나 적으면 걸린다. 소스가 바뀌면 대본이 stale임을 즉시
안다.

## 챕터

```markdown
## CHAPTER 1 — 화면에 뜰 제목
```

## 나레이션

```markdown
### [나레이션]
근거: S05 412-431
지금 벌어지는 일은 노선 다툼이 아닙니다.
```

`근거:`는 이 문단이 무엇에 기대는지다. 여러 개면 `;`로 나눈다.

```markdown
근거: S05 412-431; S02 118-126
```

**나레이션에 따옴표를 쓰지 마라.** 인용하고 싶으면 `[원본]` 블록을 써라.
그러면 원문과 자동 대조된다. 나레이션 안 따옴표는 검증에서 걸린다 —
직전 회차 최악의 지적이 정확히 그 형태였다.

자막에 근거가 없는 일반론이면 `근거:` 줄을 생략해도 된다. 다만 그런 문단이
많으면 영상이 사실이 아니라 의견이 된다.

## 원본 영상 자막

```markdown
### [원본] S05 | 00:11:23.400~00:20:07.120 | cue 412-468 | 생략 414,417-419 | 간투사 | 직접
> 실제로 화면에 뜰 발화 문자열
```

항목은 `|`로 나눈다. 순서는 상관없다.

```text
S05                     source_id. 필수
00:11:23~00:20:07       타임코드
cue 412-468             cue 범위. 선택 — 없으면 타임코드에서 역산한다
생략 414,417-419        건너뛴 cue
간투사                   생략 사유 분류
직접                     인용 방식. 필수
```

타임코드나 cue 중 **하나는 반드시** 있어야 한다. cue 번호를 세기 싫으면
타임코드만 줘라. 파서가 SRT에서 채운다.

인용문은 바로 다음 줄에 `>`로 적는다. 여러 줄이면 이어붙여 대조한다.

### 인용 방식

`[원본]`은 **`직접` 전용이다.** 화면에 뜰 발화 자막이라 원문과 대조할 수
있어야 한다. 한 글자라도 다르면 `FAIL_QUOTE_FIDELITY`다. 어미도 글자다.

대조는 **공백만 정규화하고 그 밖의 문자는 그대로** 비교한다. SRT 는 한
발화를 여러 줄로 쪼개므로 줄바꿈과 연속 공백은 차이로 보지 않는다. 조사·어미·
문장부호는 전부 차이다.

```text
원문   실패로 끝날 거라고 봐요
대본   그 선택이 실패로 끝날 것        <- 거부
```

읽기 흐름 때문에 다듬고 싶으면 **나레이션으로 옮기고** 이 구간을 `근거:`로
지목해라. 다듬은 문장에 따옴표를 남기는 것이 직전 회차 위반이다.

### 생략 분류 — 중요

연속된 영상에서 발화 cue만 빼면 자막과 화면이 어긋난다. 그래서 생략은
사유를 밝혀야 하고, 허용 분류가 정해져 있다.

```text
간투사 · 중복발화 · 비언어      허용. 영상은 연속으로 둔다
그 밖의 생략                    실제 영상 컷이다. 블록을 나눠 선언해라
분류 없는 생략                  거부
```

실제로 중간을 자를 거면 이렇게 둘로 쪼갠다.

```markdown
### [원본] S05 | 00:11:23~00:13:40 | 직접
> 앞 구간 발화

### [원본] S05 | 00:16:02~00:20:07 | 직접
> 뒤 구간 발화
```

신고한 생략은 대조에서 빠진다. **신고하지 않고 빼면 불일치로 걸린다.**

# GPT 유의사항

이론이 아니다. **직전 회차 대본 감사에서 실제로 나온 11건**을 규칙으로 굳힌
것이다. 여기서 걸러내면 검증이 조용히 지나간다.

## 1. 인용 — HIGH

따옴표 안은 원문이다. 어미·조사·어순을 하나도 바꾸지 않는다. 바꿀 거면
나레이션으로 옮기고 따옴표를 뗀다.

## 2. 법률·제도 용어 — HIGH

표준 용어만 쓴다. 그럴듯한 조합을 만들지 않는다.

```text
공소 검사                          표준 아님. 실제 지적 사례
공소청 검사 / 기소 검사             맥락에 맞는 것

보완수사권 · 공소청 · 중수청 · 형사소송법 · 직접수사권
국가수사본부 · 고위공직자범죄수사처
```

## 3. 정치 담론 조어 금지 — HIGH

```text
'반명'이라는 신분 판정      실제 지적 사례. '신분 판정' 은 통용어가 아니다
진영 판정 / 꼬리표          통용어
```

## 4. 근거 범위를 넘지 않는다 — HIGH

`근거:`에 적은 cue를 실제로 읽고, 거기 없는 주장은 쓰지 않는다.

```text
근거   진행자가 "'뉴 이재명' 진영 구축" 이라고 해석
대본   "실패의 대상이 '이재명 대통령' 과 '이재명 정부' 로 확장"
결과   대통령 개인으로의 확장은 자막 어디에도 없다. 무근거 확대
```

기계는 인용 문자열만 본다. 이건 사람이 잡는다.

## 5. 의혹은 끝까지 의혹이다 — HIGH

이번 회차 최대 위험이다. 수집 소스 8개 중 4개 제목에 신천지가 들어간다.
수집보고서가 이미 경고를 붙였다.

> 제목에 포함된 '신천지 개입' 등의 표현은 각 영상·출연자의 주장 또는 의혹
> 제기입니다. 해당 주장을 사실로 확정하지 않습니다.

```text
허용   ~라는 의혹이 제기됐다 / ~라고 주장했다 / ~라고 밝혔다
       ~라는 의혹을 두고 공방이 벌어졌다
금지   ~로 드러났다 / ~가 밝혀졌다 / ~한 것으로 확인됐다
       (자막에 확정 근거가 있고 주체를 밝힐 때만)
```

누가 주장했는지 항상 밝힌다. 주어 없는 확정 서술은 제작자의 주장이 된다.

## 6. 없던 비유를 갑자기 꺼내지 않는다 — HIGH

```text
"단순한 예방주사"      실제 지적 사례. 앞에 등장한 적 없는 비유가 돌출
```

## 7. 한 문장 안에서 어미를 섞지 않는다 — HIGH

```text
"갖는지 / 배치되는지"  와  "통제할지 / 마무리할지"      한 문장에 혼용
```

## 8. 비교급과 서술어의 호응 — HIGH

```text
"원칙보다 ... 충돌합니다"      '~보다' 는 '충돌하다' 와 호응하지 않는다
"원칙이 아니라 ... 충돌합니다"
```

## 9. 인물 표기를 대본 전체에서 통일한다 — MEDIUM

```text
직전 회차   박은정 의원 · 김용민 의원 은 직함 유지
            박원석 만 나레이션에서 직함 탈락
```

첫 등장에서 `직함 + 이름`, 규칙을 정했으면 끝까지 지킨다.

## 10. 제작 메모를 대본에 남기지 않는다 — MEDIUM

```text
화자 필드   "진행자 소개 기준 김재현 오마이뉴스 기자"      실제 지적 사례
```

유보가 필요하면 본문이 아니라 별도 메모로 적는다.

## 11. 접속어와 결론 — LOW

```text
"반대로"      대비 관계면 '반면'
결론 중복      "확정할 수 없습니다" 와 "결정할 것입니다" 가 나란히 오면 하나만
```

# 넘기기 전 자체 점검

여기서 잡으면 왕복이 줄어든다.

```text
1  '직접' 으로 적은 인용을 source_packet 원문과 대조했는가
2  나레이션에 따옴표가 없는가
3  근거 cue 를 실제로 읽고 그 범위 안의 주장만 썼는가
4  생략마다 허용 분류(간투사·중복발화·비언어)를 붙였는가
5  실제 영상 컷은 블록을 나눴는가
6  의혹 사안에 주체와 '의혹·주장' 표현이 붙어 있는가
7  법률 용어가 위 목록 표기와 일치하는가
8  인물 지칭 규칙이 대본 전체에서 하나인가
9  narration_blocks · source_clips 가 실제 개수와 맞는가
```

# 기계가 잡는 것 / 사람이 잡는 것

```text
기계   인용 문자 불일치 · cue 범위 밖 · 없는 source_id
       나레이션 따옴표 · 미분류 생략 · 개수 불일치
       의혹의 확정 서술 · 패킷 지문 불일치

사람   근거 범위 초과 · 논리 비약 · 비문 · 어미 혼용
       인물 표기 불일치 · 제작 메모 누출 · 결론 중복
       인용은 정확한데 앞뒤를 잘라 뜻이 뒤집힌 경우
```

기계가 0건이어도 사람 검수는 남는다. Claude가 읽는 것은 **나레이션 전문과
인용된 cue 창**이지 자막 전량이 아니다.

# Claude가 하는 일 / 하지 않는 일

```text
한다        원문 대조 · 표기 확인 · 기계 검증 · 지적서 작성 · 최종 확인
하지 않는다  논지 수정 · 문장 재작성 · 인용 교체 · 챕터 순서 변경
```

지적은 GPT에 돌아가고 **판정은 GPT가 한다.** Claude가 고쳐서 통과시키면
`FAIL_EXECUTOR_EDITED_SCRIPT`다.
