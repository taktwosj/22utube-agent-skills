# 티키타카 대본 만들기 스킬 v1.7

## 목적

Gemini 영상 분석 JSON과 상위 댓글을 받아서 작동 이유를 다중 추출하고, 5명 광팬 에이전트 관점으로 좋아하는 구간을 본 뒤, 한 번에 1질문으로 원본과 다른 후크, 순서, 시점의 3단 분리 짜깁기 대본을 만든다.

## 트리거

사용자가 `이거 분석해줘`, `이걸로 해보자`, `티키타카 시작`, `티키타카 대본`, `하단 첫마디 후보`, `후크 5개`라고 하거나 Gemini JSON과 댓글을 주고 대본 방향을 잡자고 하면 적용한다.

입력:

- Gemini 영상 분석 JSON: 필수
- 상위 좋아요 댓글 10-30개: 선택, 정확도 상승
- 조회수/채널 정보: 선택

## Gemini v2.1 원자료 신호 사용

Gemini JSON은 최종 진실이 아니라 초벌 원자료다. 다음 필드가 있으면 티키타카 결정의 증거로 사용하되, 최종 대본에서는 과장과 오류를 정리한다.

```text
source_audio_mode
source_audio_mode_evidence_ko
youtube_category_raw
content_mode_raw
category_point_inventory
implemented_point_timeline
emotion_timeline
visual_focus_timeline
dialogue_timeline
dialogue_function_timeline
music_lyric_timeline
reaction_timeline
character_state_timeline
edit_impact_points
wow_point_candidates_raw
viewer_confusion_risks
turning_points
shorts_structure_raw
remake_notes_for_codex
```

사용법:

- `youtube_category_raw`와 `content_mode_raw`로 큰 장르와 실제 작동 모드를 잡는다.
- `category_point_inventory`, `implemented_point_timeline`, `wow_point_candidates_raw`, `edit_impact_points`로 후크 후보와 하단 첫마디 후보를 만든다.
- `visual_focus_timeline`으로 시청자가 봐야 할 대상을 정한다.
- `dialogue_timeline`, `dialogue_function_timeline`, `source_audio_mode`로 따옴표 대사 사용 가능 여부를 정한다.
- `music_lyric_timeline`은 음악 신호이며 인물 대사가 아니다.
- `viewer_confusion_risks`는 하단 TTS가 설명해야 할 맥락으로 사용한다.
- Gemini의 `possible_caption_angles_ko`와 `remake_notes_for_codex`는 아이디어일 뿐 사실 권위가 아니다.

## source_audio_mode 대사 잠금

- `background_music_only`이면 중단에 `"..."` 인물 대사를 만들지 않는다.
- 배경음악만 있는 영상은 괄호 자막, 시각 상황, OCR, 음악 가사 맥락, 하단 내레이션 중심으로 쓴다.
- 실제 대사가 있는 영상만 따옴표 대사를 허용한다.
- 소스 오디오가 불명확하면 000short-production-agent가 source.mp4로 확인하기 전까지 따옴표를 피한다.

## 진행 7단계

1. 1차 인상
   - `흠. 이런 영상이군. ...` 형식으로 2-3줄 요약.
2. 5명 광팬 에이전트 병렬 분석
   - 각자 좋아하는 구간과 이유 1줄.
   - 공통 구간 도출.
3. 작동 이유 다중 추출
   - 후보 4-7개와 점수.
   - 진짜 작동 이유는 상위 2-3개.
4. 댓글 분석
   - 댓글이 있을 때만 수행.
   - 댓글 신호로 작동 이유를 재조정.
5. 톤 분류
   - 6가지 톤 중 선택.
6. 결정 트리 대화
   - 한 번에 1질문.
   - 추천 답과 이유 제공.
   - 한 가지 결정 후 다음 질문.
   - 멈춤 신호 존중.
7. 3단 분리 대본 작성
   - 사용자가 후크를 선택한 뒤에만 작성.

## 결정 트리 순서

1. 작동 이유 확정: 1-3개.
2. 후크 결정.
3. 순서 변환 결정.
4. 자막 톤 결정.
5. 하단 첫마디 후크 5개 제시 후 사용자 선택.
6. 대본 작성.

## 5명 광팬 에이전트

```text
[10대 - 김찬우]
관심: 챌린지, 밈, 짧고 강한 임팩트
패턴: 가장 어이없거나 충격적인 구간

[20대 - 박지은]
관심: 반전, 케미, 리얼리티
패턴: 의외성/반전

[30대 - 이상민]
관심: 사연, 인생사, 공감
패턴: 감정/억울/통쾌

[40대 - 정혜진]
관심: 자녀/가족/사회
패턴: 교훈/메시지/현실

[50대 - 박철수]
관심: 향수, 권력, 사연
패턴: 반전/통쾌/회한
```

## 6가지 톤

```text
A. 일본 예능 / 실험 / 검증
대본: 상황 설명 + 호기심 후크
시점: 3인칭

B. 사연 / 감동 / 인터뷰
대본: 감정 진입 + 시-풀이
시점: 1인칭 가능

C. 음악 / 반전 / 성덕
대본: 역설 후크 + 점층
시점: 3인칭

D. 인물 / 띠동갑 / 발언
대본: 최강 인용 후크
시점: 3인칭 + 인용 살림

E. 동물 / 일상 / 귀여움
대본: 의인화 + 시각 우선
시점: 1인칭 의인화 가능

F. 추리 / 사건 / 야담
대본: Mystery-Sacrifice 템플릿
시점: 3인칭 또는 1인칭
```

## 순서 변환

```text
원본: 1(도입) - 2(상황) - 3(충격) - 4(점층) - 5(Payoff)

1. 31245: 충격 먼저
2. 51234: 결과 먼저
3. 31234+5: 충격 후 정상 흐름
4. 12354: Payoff 직전 충격
```

추가 옵션:

- 닭 표정 루프형: 의인화 영상.
- 미스터리 자막 + 티저: 반전 영상.
- 인용 폭격형: 인물/발언 영상.

## 영상 분류 A/B

```text
분류 A: 자막 없이 봐도 이해됨
- 동물, 웃긴 상황, 시각 충격
- 음악 우선
- 자막 자립 필수
- 의인화 적극

분류 B: 상황 설명 후킹 필요
- 예능, 사연, 스포츠, 사건
- 대본 우선
- 인물/사건 명확
```

## 3단 자막 구조

```text
[상단] 고정 제목
- 2줄 이내

[중단] 초단위 상황 설명
- ( ) = 감정/상태/상황/반응/의성어/댓글코드. 자유 창작.
- " " = 영상 인물 실제 말. 수정 금지.

[하단] TTS 대본
- 시간대별 단정체
- 자막 자립 필수
- 위치 선언, 모순 진입, 결정적 장면 한 줄 압축
```

## v5 핵심 룰

- 시-풀이 교차.
- 한 줄 압축.
- 단정체.
- 감정 단어 적극 사용.
- 위치 선언: `여기`, `이 닭`, `이 사람`.
- 모순 진입.
- 결정적 장면 한 줄 압축.
- 괄호 자막으로 시청자 반응 강제.

## 차별화 5요소

원본과 달라져야 하는 영역:

1. 구도: 순서/시점.
2. 영상 자료: 배경/컷 사용.
3. TTS 보이스.
4. BGM.
5. 자막 디자인.

## 원본 인용 룰

```text
" " = 영상 음성 그대로. 수정 금지.
( ) = 자유 창작.
하단 TTS = 우리가 만드는 내레이션.
```

## 하단 첫마디 후크 5개 룰

첫 줄이 약하거나 대본 작성 전이면 먼저 이 단계만 출력한다.

```text
하단 첫마디 후보 5개
1. ...
2. ...
3. ...
4. ...
5. ...

My recommendation: ...
Reason: ...
Your choice:
1
2
3
4
5
```

사용자가 1-5 중 하나를 고른 뒤에만 상단/중단/하단/하단 원문을 작성한다. 다른 후크별 풀버전은 만들지 않는다. 사용자가 `너가 알아서`라고 하면 추천 번호로 결정하고 진행한다.

## 댓글 분석 카테고리

1. 특정 구간 언급.
2. 시점/연령 단서.
3. 공감 코드.
4. 바이럴 인용: 가장 중요.
5. 부정 신호.
6. 의미 없음: 제외.

## 대화 톤

- 짧게 답한다.
- 객관적으로 평가한다.
- 한 번에 1질문.
- 추천 답을 제공한다.
- 결정은 사용자에게 맡긴다.
- 선택지는 숫자로만 제시한다.
- 사용자가 결정하기 전에는 굳이 다 하지 않는다.
- `그만`, `됐어`, `다음`, `바로 써`, `프로젝트 만들어`는 멈춤/진행 신호로 존중한다.

## 최종 출력 형식

복사 가능한 일반 Markdown 텍스트로만 출력한다. 레이어 순서는 반드시 유지한다.

```text
상단
2줄 제목

중단
[0~2초]
( ) 자막
" " 실제 인용

하단
[0~2초]
TTS 대본

하단 원문
TTS만 시간 표시 없이
```

규칙:

- `하단 텍스트 복사용`은 쓰지 않는다.
- `하단 원문`은 시간 표시 없는 하단 TTS/내레이션 원문만 담는다.
- `중단`과 `하단`을 한 타임라인으로 합치지 않는다.
