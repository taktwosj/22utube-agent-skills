# 척추대본 119 보고 형식

회차를 다 만들고 보고할 때 아래 두 덩어리를 이 순서로 낸다. 게이트 PASS 나열이나 카드 수 같은 내부 지표를 앞에 두지 않는다.

## 1. 산출물 (먼저)

사용자가 CapCut을 열고 유튜브에 올릴 때 실제로 필요한 값이다.

```text
프로젝트명   <CapCut 프로젝트명>
             <프로젝트 전체 경로>
미디어       <capcut_media 절대경로>
제목         <업로드 제목>
내용         <설명란 요약 + 타임라인 + 출처. 그대로 붙일 수 있게>
썸네일       <단어 3개>
             <문장 3줄>
```

값은 `pre119_handoff.json` 의 `publication_report` 에서 그대로 가져온다. 새로 쓰지 않는다.
출처는 `출처 : <채널명>` 만 쓴다.

## 2. 검증 (뒤에)

```text
RESULT: PASS | WAIT | FAIL

회차 id     <episode_id>
길이        <초> = <분>
척추        <초> = <분> = <퍼센트>   (오프닝 재사용 제외)
살          <초> = <퍼센트>
나레이션     <초> = <퍼센트>
카드 수      <n> (SRC <n> / NAR <n>)
소스 편수    <n>편 <n>채널 (channel_id 실측 여부)

검증  validator / compile / preflight / build / readback  각각 PASS·FAIL
자막  cue <n> | 15자 초과 <n> | 2줄 <n> | 5자 이하 <n>
      타이밍 드리프트 중앙값 <초>, 0.6s 초과 <n>/<n>
humanize  risk_band=<값>, 실행 여부 (영상 100%면 NOT_REQUIRED)

SKILL_FIX_NEEDED: 목록 또는 없음
NOT RUN: 목록

NEXT: 한 가지 행동
```

## 척추 배치 표

척추를 한 덩어리로 넘기지 않았음을 보이는 표를 넣는다.

```text
<시각>  척추①  <챕터 문구>   <길이>
<시각>  척추②  <챕터 문구>   <길이>
...
```

## 규칙

- 실행하지 않은 검증을 PASS로 쓰지 않는다. 미실행은 `NOT RUN`.
- 12분을 못 채웠으면 PASS로 보고하지 않는다.
- 척추가 50% 미만이면 PASS로 보고하지 않는다.
- `MEDIA_RELINK` FAIL 은 정상이다. 릴링크는 사용자 작업이라고 적는다.
- 긴 로그를 붙이지 않는다. 결론·최초 실패·다음 행동만 쓴다.
- 스킬 결함은 중간에 멈춰 묻지 말고 이번 회차 한정으로 우회한 뒤 `SKILL_FIX_NEEDED` 로 일괄 보고한다. 데이터 손상이나 되돌리기 어려운 작업은 예외로 멈춰 묻는다.
