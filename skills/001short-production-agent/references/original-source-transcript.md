# 원본 5분류 대본 계약

Stage 01에서 증거를 확보하고 Stage 02의 `original-capcut-grid.md`에 기록한다. 15개 물리 트랙과 15행 표는 그대로 유지한다.

새 에피소드 bootstrap은 intake receipt v2와 state에 `original_analysis_contract_version=001short-original-source-transcript-v1`을 함께 기록한다. 기존 state와 intake v1에 이 값이 없으면 legacy resume이며 5분류 대본을 새로 요구하지 않는다. 한쪽에만 값이 있거나 값이 다르면 실패다.

## 증거 확인

각 자막·화자·나레이션·화면 변화점에서 `B01…BN`을 나눈다. 화면 글자가 흐리거나 겹치면 해당 구간의 고해상도 키프레임을 다시 뽑아 확대 확인한다. 원음은 source audio와 원본 caption/transcript를 함께 대조한다. OCR을 끝내 판독하지 못하면 `WAIT_OCR_UNRESOLVED`로 멈춘다. 상황 자체가 미확정이면 `ORIGINAL_TRANSCRIPT_UNVERIFIED`로 멈춘다.

OCR은 들린 말이 아니다. 화면에 baked된 글자는 `(상황설명)`의 `화면 OCR:` 뒤에 원문 그대로 쓰고, 원음은 `"화자발언"` 또는 `<나레이션>`에만 쓴다. 원본 단계에서 새 TTS를 추정하거나 작성하지 않는다.

새 계약의 Stage 01은 `10_analysis/original-source-evidence.json`을 `schemas/original_source_evidence.schema.json`으로 작성한다. state는 이 경로와 SHA-256을 `original_source_evidence_path`, `original_source_evidence_sha256`에 고정한다. 각 B구간 증거는 다음을 모두 가진다.

- source identity 경로·SHA와 source media 경로·SHA
- source range
- 고해상도 keyframe 경로·SHA·timestamp·literal OCR
- source transcript/caption evidence 경로·SHA
- source audio evidence 경로·SHA
- 다섯 분류의 확정 문자열; 두 TTS 값은 `없음`

## 고정 형식

15행 표보다 먼저 모든 B구간을 source 순서대로 쓴다. 구간 ID와 시작·종료 시간은 바로 뒤 15행 표의 `Bxx <start>–<end>` 머리글과 정확히 같아야 한다. 각 블록은 다음 다섯 줄을 같은 순서로 한 번씩만 가진다.

```text
### B01 0.000–3.900
(상황설명) 실제 보이는 상황. 화면 OCR: 원문 또는 없음
"화자발언" 실제 원음 발언 또는 없음
<나레이션> 실제 원본 보이스오버 또는 없음
TTS화자발언 없음
TTS나레이션 없음
```

- `(상황설명)`: 인물·행동·사물·구도와 literal baked OCR. OCR이 없으면 `화면 OCR: 없음`.
- `"화자발언"`: 화면 속 인물에게서 실제 들리는 원음 발언. 화면자막을 복사해 발언으로 만들지 않는다.
- 같은 B구간에 화자가 둘이면 한 줄에 `"화자발언" [A] 첫 화자 원문 / [B] 둘째 화자 원문`으로 쓴다. A는 `A10_TEXT_WHITE`, B는 `A10_TEXT_YELLOW`에 대응한다. 한 명뿐이면 `[A]`만 쓴다.
- `<나레이션>`: 실제 source voiceover나 off-screen 해설. source narration을 TTS로 분류하지 않는다. **분석 기록용이다 — 원본 나레이션 음성은 최종 제작에 반입하지 않는다.** A10으로 유지 가능한 원음은 검증된 화자발언뿐이며, 해설이 필요하면 우라까이에서 `TTS나레이션`을 새로 쓴다.
- `TTS화자발언`, `TTS나레이션`: 편집으로 새로 추가할 음성 자리. 원본 재구성에서는 항상 `없음`.
- 부재는 정확히 `없음`; 빈값·`비움`·`미확인`·`확인 필요`를 쓰지 않는다.

## 화자발언·나레이션·상황설명 판정 규칙

0. **음성 우선**: 발언 분류(화자발언/나레이션)는 사람 목소리가 실제로 있을 때만 한다. 화면에 글자만 박혀 있고 소리가 BGM·효과음·무음이면 그 글자는 `(상황설명)`이다 — 화자발언도 나레이션도 아니다.
1. **OCR로 1차 추측**: 문장 성격으로 나눈다. 나레이션 신호 = 설명·서술형 어미(`~하는데요`, `~없었죠`, `~때문인데요`, `~됩니다`, `~있습니다`, `~일까요`, `~합니다/였습니다`), 시청자에게 설명하는 말투, 장면 요약. 화자발언 신호 = 반말·구어체 대화, 질문↔대답, 감탄사·호칭, 현장 반응.
2. **화자 수 추측**: 대화 주고받기, 자막 색·위치 변화, 화면 인물 수로 1명/2명을 추정해 `[A]`/`[B]`에 배정한다.
3. **음성으로 확정**: 실제 청취(STT)와 입모양 동기화·음색·화자전환으로 OCR 추측을 확정하거나 수정한다. OCR만으로 화자를 확정하지 않는다. 화면 글자와 음성이 동시에 나와도 문장이 서술형이면 화자발언이 아니라 `<나레이션>`이다.

## 검증

Stage 02에서 원본표만 먼저 검증한다.

```text
python -B scripts/validate_capcut_grids.py \
  --original <episode_root>/20_script/original-capcut-grid.md \
  --original-only
```

검증기는 canonical episode 경로에서 state와 intake를 자동으로 읽는다. CLI flag로 계약 버전을 선택하지 않는다. 새 버전이면 evidence 파일과 모든 참조 파일의 SHA, B구간·시간·OCR·화자발언·나레이션·TTS 값을 원본표와 대조한다. Stage 03 이후에는 기존 원본표·우라까이표 전체 검증 명령을 그대로 실행한다.

## Stage 01 판독 실무 (260817 5편 배치에서 확정)

### 검증 깊이 — 여기에 힘을 쓰고 여기는 빼라

| 대상 | 기준 | 이유 |
|---|---|---|
| 구간 경계·시간 | **엄격**. 놓친 경계 하나가 하류 전체를 무효로 만든다 | 자막 텍스트가 한 칸씩 밀려도 표·오디오·자막 잠금이 전부 PASS로 통과한다. 조립 직전에야 드러난다 |
| 화자 / 나레이션 / 상황자막 구분 | **엄격**. 유형이 여기서 갈린다 | 화자발언 유무가 가능한 유형을 1·2로 좁힌다 |
| 자막 문구 | **1회 판독으로 끝**. 교차판독·확대검증 하지 마라 | 어차피 우라까이에서 우리 문장으로 새로 쓴다. `수로`/`수도` 차이는 결과물에 영향이 없다 |
| 화면 구성 묘사 | 의도만 | 조립에 쓰이지 않는다 |

문구를 글자 단위로 맞추는 데 시간을 쓰지 마라. **틀리면 안 되는 건 "어느 시간대에 무엇이 있었나"이지 "정확히 어떤 글자였나"가 아니다.**

### 자막 문구 판독은 Codex에 위임한다

`codex exec`는 이미지를 받는다. 자막 대역 시트를 그대로 넘기면 된다.

```bash
codex exec --cd <crops-dir> --sandbox read-only --skip-git-repo-check \
  -m gpt-5.6-terra -c model_reasoning_effort="high" \
  -i sheet_01_08.png -i sheet_09_16.png ... - < prompt.md
```

- `-i`는 **파일마다 하나씩** 쓴다. 셸 변수에 모아 확장하면 뒤따르는 `-` 위치 인자가 깨진다.
- 실측 정확도: 41구간 90%, 29구간 97%, 32구간 100%.
- 프롬프트에 **"맞춤법·오타를 고치지 마라"를 반드시 넣어라.** 그래도 모델이 정규화하려 든다
  (화면의 `민동산`을 `민둥산`으로 고쳐 읽은 사례). 원본표는 화면 그대로가 원칙이다.
- 확신 낮은 구간을 `SUSPECT`로 표시하게 하라. 실제 오독과 잘 맞는다.
- tesseract는 이 용도로 쓰지 마라. 흰 배경 검은 고딕에서도 41개 중 37개가 깨졌다.

### 자막 대역은 잘림 자가검사를 통과해야 한다

대역을 눈대중으로 잡으면 틀린다. 4편 중 2편이 틀렸고, 한 편은 자막이 통째로 크롭 밖이었다.

확정한 crop으로 실제 크롭을 뽑은 뒤:

- **크롭의 맨 윗줄·맨 아랫줄 픽셀에 글자 마스크가 남아 있으면 그 방향으로 대역이 부족하다.**
- 여러 시각(최소 8개, **2줄 자막이 나오는 시각을 반드시 포함**)에서 이 검사를 돌려
  모든 시각에서 위아래 가장자리가 빌 때까지 넓혀라.
- 고정 요소(채널 배지, 고정 제목, 댓글 카드)는 대역에서 제외한다.

### 영상 위에 겹친 자막은 raw MAD를 쓰지 마라

배경 영상이 움직이면 프레임 차분이 자막 전환과 구별되지 않는다. **텍스트 마스크 XOR**를 써라.

1. 그레이스케일 → 글자에 해당하는 픽셀만 이진 마스크로 남긴다
   (흰 글씨 + 검은 외곽선이므로 매우 밝은 픽셀, 또는 국소 대비가 큰 픽셀. 히스토그램을 보고 임계를 정한다).
2. 프레임 간 **마스크 XOR 픽셀 수**를 지표로 쓴다. 자막이 바뀌면 튀고 배경만 움직이면 거의 안 변한다.

하단 흰 패널에 검은 글씨가 놓이는 형태는 raw MAD로 충분하다.

### STT를 경계 검증에 써라

발화가 있는 영상에서 자막 경계는 발화 경계와 **0.2~0.4초 안에서** 대응한다(자막이 조금 늦게 끝난다).

- 0.6초 이상 어긋나는 구간이 있으면 그 구간에 **놓친 경계**가 있다.
- **대응이 0건이면 자막 대역 자체가 틀린 것이다.** 실제로 이 신호로 잘못된 대역을 잡아냈고,
  대역을 고치자 같은 영상의 구간이 29개에서 32개로 늘고 미대응이 0이 됐다.

### evidence의 OCR 바인딩 규칙

`validate_original_source_evidence.py`는
`classified_fields.situation_description`을 `"화면 OCR:"`로 잘라 **그 뒤 문자열과 `literal_ocr`를 정확 비교**한다.
상황설명은 반드시 `... 화면 OCR: <자막문구>`로 끝나야 한다. 이걸 놓치면 전 구간이
`ORIGINAL_SOURCE_OCR_EVIDENCE_MISMATCH`로 떨어진다.

### 연속 동일 문구는 병합한다

경계 검출은 자막이 안 바뀌어도 화면 변화로 경계를 잡을 수 있다(과분할).
연속한 구간의 문구가 **완전히 같으면 하나의 B로 병합**하고 번호를 다시 매겨라. 병합 내역을 transcript에 남긴다.
과분할은 병합으로 고칠 수 있지만 **누락은 못 고친다** — 그래서 임계는 느슨하게 잡고 병합으로 정리하는 편이 안전하다.
