# 구조 설계도 보고 형식

원본 쇼츠의 구조를 분석하거나 우라까이 수정 구조를 보고할 때 사용한다.

## 기본 표시 순서

### 새 원본 분석 단계

새 URL이나 새 원본을 처음 분석할 때는 다음 순서를 사용한다.

1. `원본 설계도` 표
2. 원본 전체 흐름 한 줄
3. 구조 이동 추천을 한두 줄로 간단히 제시
4. 운영자 방향 확인

이 단계에서는 변경된 수정 구조의 target 시간표, T1/T2, TTS, production plan을 먼저 만들거나 보여주지 않는다.

### 수정 방향 승인 이후

운영자가 추천 방향을 확정했거나 기존 승인안을 비교해 달라고 요청했으면 다음 순서를 사용한다.

1. `변경된 수정 구조`
2. `원본 설계도`
3. `원본과 수정본 비교`
4. 구조 순서 한 줄 요약

승인 이후의 비교 보고에서는 수정 구조를 원본보다 뒤에 두지 않는다. 운영자가 표를 캡처하거나 다른 문서의 왼쪽에 붙일 수 있도록 수정안을 먼저 보여준다.

## 필수 표 열

| 열 | 작성 규칙 |
|---|---|
| 시간 | 원본 시간과 수정 후 시간을 혼동하지 않는다. 수정표에는 target range, 원본표에는 source range를 쓴다. |
| 구조 | `구조 1`, `구조 5A`, `구조 5B`처럼 장면 순번을 표시한다. |
| 전달 방식 | 아래의 고정 분류 중 실제 소리 구성에 맞는 값을 쓴다. |
| 구조 유형 | 도입·문제 제기, 변명·대립, 비교·검증, 직접 행동, 결과 훅, 결과 완성, 결말 등 서사 기능을 쓴다. |
| 화면 | 실제로 보이는 인물·차량·사물·행동·카메라 구도와 장면 변화를 쓴다. |
| 화면 텍스트 | 상단 고정 제목, 영상 안 대사 자막, 하단 상황 설명, 강조 문구, 워터마크를 구분해 적는다. clean 파일에서 제거된 글자도 원본 분석에는 기록한다. |
| 화자·대사 | 해당 구간에서 실제로 들리는 화자 발언·TTS·나레이션을 화자와 대사 순서대로 쓴다. 자동자막·OCR이 불확실하면 `확인 필요`를 표시한다. |
| 들리는 소리 | 경적, 엔진음, 도로 현장음, 사람 고성, 충돌음, 추가 효과음 등 실제 청각 요소를 적는다. `현장음` 한 단어로 뭉개지 않는다. |
| 상황 설명 | 위 화면·글자·대사·소리가 합쳐져 어떤 사건이 진행되고 서사에서 어떤 역할을 하는지 설명한다. 단순 줄거리 요약으로 앞 항목들을 대체하지 않는다. |

## 원본 증거와 해석 분리

원본 설계도에는 각 항목의 권위를 표시한다.

- `SOURCE_OBSERVATION`: 프레임에서 직접 보이는 차량·인물·행동·구도
- `TRANSCRIPT`: 원본 음성 또는 원본 자동자막에서 확인된 발언. 자동자막 오인식 가능성을 주석으로 남긴다.
- `SCREEN_LABEL`: 영상 제작자가 화면에 붙인 화자명·행동명
- `SCREEN_CLAIM`: 하단 상황 설명·감정 평가처럼 영상 제작자가 주장한 문구
- `UNVERIFIED`: 원본으로 명확히 판독하지 못한 화자 신원·욕설·창문음·SFX·BGM

`SCREEN_LABEL`과 `SCREEN_CLAIM`은 화면에 존재한다는 사실만 확정하며, 그 내용 자체를 객관적 사실로 승격하지 않는다. `논리가 무너졌다`, `보복성이다`, `해결되지 않았다` 같은 해석은 Stage 02에서 제외하고 Stage 03 추천안으로 이동한다.

## 허용 도구 원본 매트릭스

Stage 02 문서에는 시간 구간을 가로축으로, `VIDEO·T1·T2·A9·A10·STATE·A11·A12·SCREEN`을 세로축으로 한 매트릭스를 반드시 포함한다. 긴 영상은 같은 세로축을 유지한 채 표를 여러 개로 나눌 수 있다. 시간 구간은 실제 자막·화자·행동·음향·화면 처리 변화 시점으로 정하며 임의의 동일 간격을 사용하지 않는다.

## 전달 방식 고정 분류

- `화자 발언`: 영상 속 등장인물의 실제 원본 음성
- `단순 TTS`: 한두 문장의 AI 음성 훅 또는 브리지
- `나레이션`: 상황과 의미를 설명하는 연속 해설
- `효과음만`: 화자 발언 없이 효과음·현장음만 존재
- `영상 재생만`: 별도 TTS·나레이션·화자 음성을 사용하지 않고 화면만 재생
- `화자 발언 + 현장 효과음`: 실제 대사와 현장음이 함께 존재
- `단순 TTS + 영상 재생`: 원본 음성을 음소거하고 영상 위에 TTS만 배치

`영상 재생만`은 화면 역할을 뜻하는 표현으로 추측해서 붙이지 않는다. 실제 A10이나 원본 화자 음성이 살아 있으면 `화자 발언` 또는 `화자 발언 + 현장 효과음`으로 쓴다.

## 상황별 구조 구분 원칙

구조는 기존 번호나 정해진 초 단위로 기계적으로 자르지 않는다. 원본을 먼저 보고 다음 변화점에서 회차별 구조를 나눈다.

- 상황 또는 장소가 바뀌는 지점
- 행동의 목적이 바뀌는 지점
- 주도 화자나 대화 관계가 바뀌는 지점
- 전달 방식이 `화자 발언`, `단순 TTS`, `나레이션`, `효과음만`, `영상 재생만` 등으로 바뀌는 지점
- 서사 기능이 도입·충돌·검증·행동·반전·결과·결말 등으로 바뀌는 지점

구조 개수와 번호는 영상마다 달라진다. 우라까이의 핵심은 특정 구조를 분할하는 것이 아니라, 상황별로 구분한 구조의 순서와 연결 관계를 새롭게 설계하는 것이다.

## 조건부 A/B 분할 표기

하나의 원본 상황 안에서 앞부분과 뒷부분의 기능이 실제로 달라지고, 일부를 선행 훅으로 사용해야 할 때만 A/B 분할을 사용한다. A/B 분할은 필수 규칙이 아니다.

결과 구간 일부를 선행 훅으로 쓰는 회차라면 원본 구조 번호를 삭제하거나 같은 구간을 중복 재생하지 않는다.

```text
원본: 구조 5
수정: 구조 5A 결과 훅 + 구조 5B 결과 완성
```

각 행에는 source range와 target range를 기록하고, 5A와 5B가 같은 source range를 통째로 반복하지 않는지 검증한다.

## 실제 프로젝트와 보고서 일치

- 표의 전달 방식은 CapCut의 실제 A9/A10 배치와 일치해야 한다.
- 오프닝 원본 음성을 mute했다면 `단순 TTS + 영상 재생`으로 쓴다.
- A10이 재배치되어 살아 있으면 `영상 재생만`으로 쓰지 않는다.
- 원본 분석표가 30초까지만 있어도 실제 원본·수정본에 31초 이후 결말이 있으면 별도 구조 행으로 표시한다.
- 자동자막 오인식은 원문과 문맥상 정리본을 구분하고, 교정 사실을 주석으로 남긴다.

## Markdown 산출물

운영자가 `MD 파일로 정리`를 요청하면 회차 `20_script/` 또는 지정 문서 폴더에 다음 순서로 저장한다.

```text
문서 정보
변경된 수정 구조
원본 설계도
원본과 수정본 비교
전달 방식 구분 기준
최종 판정
```

저장 후 파일을 다시 읽고 실제 경로와 byte size를 확인한 뒤 전달한다.
