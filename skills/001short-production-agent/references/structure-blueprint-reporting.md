# 구조 설계도 보고 형식

원본 쇼츠의 구조를 분석하거나 우라까이 수정 구조를 보고할 때 사용한다.

## 기본 표시 순서

### 새 원본 분석 단계

새 URL이나 새 원본을 처음 분석할 때는 다음 순서를 사용한다.

1. `원본 설계도` 표
2. 원본 전체 흐름 한 줄
3. 구조 이동 추천을 한두 줄로 간단히 제시
4. 운영자 방향 확인

이 단계에서는 변경된 수정 구조의 target 시간표, T1/T2, TTS, production plan을 먼저 만들거나 보여주지 않는다.

### 수정 방향 승인 이후

운영자가 추천 방향을 확정했거나 기존 승인안을 비교해 달라고 요청했으면 다음 순서를 사용한다.

1. `변경된 수정 구조`
2. `원본 설계도`
3. `원본과 수정본 비교`
4. 구조 순서 한 줄 요약

승인 이후의 비교 보고에서는 수정 구조를 원본보다 뒤에 두지 않는다. 운영자가 표를 캡처하거나 다른 문서의 왼쪽에 붙일 수 있도록 수정안을 먼저 보여준다.

## 필수 표 열

| 열 | 작성 규칙 |
|---|---|
| 시간 | 원본 시간과 수정 후 시간을 혼동하지 않는다. 수정표에는 target range, 원본표에는 source range를 쓴다. |
| 구조 | `구조 1`, `구조 5A`, `구조 5B`처럼 장면 순번을 표시한다. |
| 전달 방식 | 아래의 고정 분류 중 실제 소리 구성에 맞는 값을 쓴다. |
| 구조 유형 | 도입·문제 제기, 변명·대립, 비교·검증, 직접 행동, 결과 훅, 결과 완성, 결말 등 서사 기능을 쓴다. |
| 화면 | 실제로 보이는 인물·차량·사물·행동·카메라 구도와 장면 변화를 쓴다. |
| 화면 텍스트 | 상단 고정 제목, 영상 안 대사 자막, 하단 상황 설명, 강조 문구, 워터마크를 구분해 적는다. clean 파일에서 제거된 글자도 원본 분석에는 기록한다. |
| 화자·대사 | 해당 구간에서 실제로 들리는 화자 발언·TTS·나레이션을 화자와 대사 순서대로 쓴다. 자동자막·OCR이 불확실하면 `확인 필요`를 표시한다. |
| 들리는 소리 | 경적, 엔진음, 도로 현장음, 사람 고성, 충돌음, 추가 효과음 등 실제 청각 요소를 적는다. `현장음` 한 단어로 뭉개지 않는다. |
| 상황 설명 | 위 화면·글자·대사·소리가 합쳐져 어떤 사건이 진행되고 서사에서 어떤 역할을 하는지 설명한다. 단순 줄거리 요약으로 앞 항목들을 대체하지 않는다. |

## 원본 증거와 해석 분리

원본 설계도에는 각 항목의 권위를 표시한다.

- `SOURCE_OBSERVATION`: 프레임에서 직접 보이는 차량·인물·행동·구도
- `TRANSCRIPT`: 원본 음성 또는 원본 자동자막에서 확인된 발언. 자동자막 오인식 가능성을 주석으로 남긴다.
- `SCREEN_LABEL`: 영상 제작자가 화면에 붙인 화자명·행동명
- `SCREEN_CLAIM`: 하단 상황 설명·감정 평가처럼 영상 제작자가 주장한 문구
- `UNVERIFIED`: 원본으로 명확히 판독하지 못한 화자 신원·욕설·창문음·SFX·BGM

`SCREEN_LABEL`과 `SCREEN_CLAIM`은 화면에 존재한다는 사실만 확정하며, 그 내용 자체를 객관적 사실로 승격하지 않는다. `논리가 무너졌다`, `보복성이다`, `해결되지 않았다` 같은 해석은 Stage 02에서 제외하고 Stage 03 추천안으로 이동한다.

## 허용 도구 원본 매트릭스

Stage 02 문서에는 시간 구간을 가로축으로, `VIDEO·T1·T2·A9·A10·STATE·A11·A12·SCREEN`을 세로축으로 한 매트릭스를 반드시 포함한다. 긴 영상은 같은 세로축을 유지한 채 표를 여러 개로 나눌 수 있다. 시간 구간은 실제 자막·화자·행동·음향·화면 처리 변화 시점으로 정하며 임의의 동일 간격을 사용하지 않는다.

### ORIGINAL_CAPCUT_GRID_REQUIRED_ROWS

원본 매트릭스는 빈 트랙 목록이 아니라 **CapCut 근본 세로줄에 맞춘 조립용 원본표**다. 모든 시간 열에 `T1`, `T2`, `A9 TTS`, `A9_TEXT`, `A10 작가 나레이션`, `A10 화자발언 1`, `A10 화자발언 2`, `A10 화자발언 3`, `STATE 상황설명문구`를 포함한다.

| 행 | 각 시간 칸에 반드시 쓸 값 |
|---|---|
| T1 / T2 | 원본 title·상단 문구 또는 `미확정 — 제목 evidence 필요` |
| A9 TTS / A9_TEXT | 원본 작가 나레이션 재현 대본과 같은 줄바꿈 문구. 한 줄 15자 이하, 축약 금지 |
| A10 작가 나레이션 | source range + 작가 해설 발화 또는 `해당 없음 — 원본 작가 나레이션 없음` |
| A10 화자발언 1~3 | source range + 화자 차례별 발화. ID 미확정이면 `화자발언 N (인물 미확정)` |
| STATE 상황설명문구 | 현재 행동·감정·관계를 나타내는 짧은 비문장 문구 |

원본 행을 단지 `없음`, `비움`, `UNVERIFIED`만으로 남기지 않는다. bare `없음`, `비움`, `UNVERIFIED`는 실패다. 실제 부재는 근거와 함께, 미확정은 확인할 evidence를 함께 쓴다. 이 표는 원본 관찰 정본이며, 최종 제목·새 TTS WAV·우라까이 문구를 선행 확정하는 문서가 아니다.

## 전달 방식 고정 분류

- `화자 발언`: 영상 속 등장인물의 실제 원본 음성
- `단순 TTS`: 한두 문장의 AI 음성 훅 또는 브리지
- `나레이션`: 상황과 의미를 설명하는 연속 해설
- `효과음만`: 화자 발언 없이 효과음·현장음만 존재
- `영상 재생만`: 별도 TTS·나레이션·화자 음성을 사용하지 않고 화면만 재생
- `화자 발언 + 현장 효과음`: 실제 대사와 현장음이 함께 존재
- `단순 TTS + 영상 재생`: 원본 음성을 음소거하고 영상 위에 TTS만 배치

`영상 재생만`은 화면 역할을 뜻하는 표현으로 추측해서 붙이지 않는다. 실제 A10이나 원본 화자 음성이 살아 있으면 `화자 발언` 또는 `화자 발언 + 현장 효과음`으로 쓴다.

## 상황별 구조 구분 원칙

구조는 기존 번호나 정해진 초 단위로 기계적으로 자르지 않는다. 원본을 먼저 보고 다음 변화점에서 회차별 구조를 나눈다.

- 상황 또는 장소가 바뀌는 지점
- 행동의 목적이 바뀌는 지점
- 주도 화자나 대화 관계가 바뀌는 지점
- 전달 방식이 `화자 발언`, `단순 TTS`, `나레이션`, `효과음만`, `영상 재생만` 등으로 바뀌는 지점
- 서사 기능이 도입·충돌·검증·행동·반전·결과·결말 등으로 바뀌는 지점

구조 개수와 번호는 영상마다 달라진다. 우라까이의 핵심은 특정 구조를 분할하는 것이 아니라, 상황별로 구분한 구조의 순서와 연결 관계를 새롭게 설계하는 것이다.

## 조건부 A/B 분할 표기

하나의 원본 상황 안에서 앞부분과 뒷부분의 기능이 실제로 달라지고, 일부를 선행 훅으로 사용해야 할 때만 A/B 분할을 사용한다. A/B 분할은 필수 규칙이 아니다.

결과 구간 일부를 선행 훅으로 쓰는 회차라면 원본 구조 번호를 삭제하거나 같은 구간을 중복 재생하지 않는다.

```text
원본: 구조 5
수정: 구조 5A 결과 훅 + 구조 5B 결과 완성
```

각 행에는 source range와 target range를 기록하고, 5A와 5B가 같은 source range를 통째로 반복하지 않는지 검증한다.

## 실제 프로젝트와 보고서 일치

- 표의 전달 방식은 CapCut의 실제 A9/A10 배치와 일치해야 한다.
- 오프닝 원본 음성을 mute했다면 `단순 TTS + 영상 재생`으로 쓴다.
- A10이 재배치되어 살아 있으면 `영상 재생만`으로 쓰지 않는다.
- 원본 분석표가 30초까지만 있어도 실제 원본·수정본에 31초 이후 결말이 있으면 별도 구조 행으로 표시한다.
- 자동자막 오인식은 원문과 문맥상 정리본을 구분하고, 교정 사실을 주석으로 남긴다.

## 조립용 상세 보고서 계약

운영자가 `상세하게`, `원본/우라까이 구조 보고`, `CapCut 조립 보고서`, `화자발언·화면설명·나레이션까지`, 또는 동등한 요청을 하면 이 계약을 사용한다. 구조 유형·순서만 나열한 요약 보고서는 금지한다.

### 보고서 순서

각 회차를 독립 단위로 아래 순서로 작성한다.

1. `회차 식별`: 원본 URL, 원본 길이, 원본 story_type, 원본 production_type, 우라까이 story_type, 우라까이 production_type, strongest hook, wow point.
2. `원본 구조`: source 순서대로 모든 구조를 세로 카드식으로 쓴다.
3. `우라까이 구조`: target 순서대로 모든 사용하는 구조를 세로 카드식으로 쓴다. 생략 구조도 범위와 생략 사유를 한 줄 남긴다.
4. `CapCut 세로 레이어`: T1/T2, A9_TEXT, A10_TEXT, STATE, ROOT_FIXED_FRAME/BACKGROUND, VIDEO, A9, A10, A11, A12를 상단→하단 논리 순서와 전체시간/조건부 여부로 적는다.
5. `CapCut 가로 시간`: target range 순서로 VIDEO source range, A9, A9_TEXT, A10, STATE의 start/end를 적는다. 긴 표는 같은 레이어를 유지한 채 여러 표로 분할한다.
6. `실행 Gate`: TTS duration, source/target range, VIDEO volume, A10/A11/A12, baked text 충돌, root 고정 레이어, CapCut preview를 `PASS`/`WAIT`/`NOT RUN`으로 구분한다.

### 원본 구조 카드의 필수 필드

각 원본 구조에는 아래 항목을 빠짐없이 쓴다.

```text
구조 ID / source start-end / 전달 방식 / 구조 역할
화면설명: 프레임에서 실제 보이는 인물·행동·사물·구도·컷
화면글자: 상단 제목, 중간/하단 자막, 워터마크, 카드·댓글·입장문을 역할과 함께
화자발언: 실제 들리는 등장인물 발화만. 없으면 "없음"
원본 나레이션: 오프스크린 나레이션·TTS만. 없으면 "없음"
들리는 소리: BGM, 현장음, 효과음, 무음 여부와 분리 가능성
서사 역할/의존성: 앞뒤 어느 구조와 왜 붙어야 하는지
사실 경계: SOURCE_OBSERVATION, TRANSCRIPT, SCREEN_LABEL, SCREEN_CLAIM, UNVERIFIED
```

화면자막을 화자발언처럼 쓰지 않는다. 화자발언이 없는 BGM/자막형은 `화자발언: 없음`, `원본 나레이션: 없음`을 명시한다. 원본 속 주장·예측·댓글·카드 글은 그 화면에 존재한다는 사실만 쓰며 독립 사실로 바꾸지 않는다.

### 우라까이 구조 카드의 필수 필드

각 target 구조에는 아래 항목을 빠짐없이 쓴다.

```text
구조 ID / target start-end / 사용하는 source ID와 source start-end / 훅·회수·맥락 역할
VIDEO: 실제 쓸 화면과 cut 경계
원본 화자발언·원본 나레이션: 원문 또는 검증된 요약, 그리고 retain/mute/duck/unused 결정
화면글자 처리: keep, cover, card, source-claim 유지 중 하나와 이유
새 A9 TTS: 실제 읽을 문장 초안. TTS가 없으면 "없음"과 이유
A9_TEXT: A9와 같은 문장·시간, 또는 없음
STATE/A10/A11/A12: 실제 배치 또는 빈값
의존성 해결: 앞 구조에서 무엇을 공급하고 다음 구조에서 무엇을 회수하는지
금지사항: 추정 화자, 사실화 금지, 중복 source, 고립 질문/답변, baked 자막 충돌 등
```

`새 A9 TTS`에는 “결과를 먼저 보여준다”, “맥락을 설명한다” 같은 편집 메모를 쓰지 않는다. 조립 가능한 실제 문장을 쓴다. WAV가 아직 없으면 `TTS 초안 / WAIT_TTS_DURATION_MEASURED`로 표시하며, 생성하지 않은 음성의 길이·자막 시간을 확정값처럼 쓰지 않는다.

### 모바일 전달 규칙

- 원본 구조와 우라까이 구조의 본문은 4열을 넘는 넓은 표 하나로 만들지 않는다. 각 구조를 `#### 구조 ID · 시간 · 역할` 제목 아래 세로 bullet/card로 쓴다.
- 표는 CapCut 가로 시간·layer matrix 같은 축 정보에만 사용하며, 휴대폰에서 가로 스크롤이 필요하면 같은 열을 유지해 여러 표로 나눈다.
- 원본 구조와 우라까이 구조를 각각 완결된 블록으로 둔다. “원본 표는 앞쪽, 대사표는 문서 끝”처럼 필수 정보를 흩어 놓지 않는다.
- HTML로 전달할 때는 UTF-8, 한 회차씩 접을 수 없는 세로 구조, 고정 폭 방지, 표 헤더 중복 금지를 검증한다.

### 최소 금지 규칙

- `화면 역할`, `TTS 역할`, `상황 설명`만 쓰고 실제 대사·나레이션·TTS 문장을 생략하지 않는다.
- source time과 target time을 같은 열이나 같은 숫자로 혼동하지 않는다.
- 원본 음성을 mute하면서 A10을 유지했다고 쓰거나, A10이 비어 있는데 원본 화자발언을 사용한다고 쓰지 않는다.
- BGM 미지정 상태에서 새 BGM이 들어간 것처럼 쓰지 않는다.
- root track-array 순서를 실제 visual z-order로 단정하지 않는다. root 고정 레이어는 보존하고 실제 렌더/GUI 검증 전 z-order를 확정하지 않는다.
- 구조 설계 `PASS`와 TTS WAV·CapCut 조립·render의 상태를 하나의 완료로 합치지 않는다.
